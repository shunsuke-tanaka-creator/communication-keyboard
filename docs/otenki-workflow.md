# お天気分・場所と生活パターン研究版

対になる `switch_bot_python` の研究版と同時に利用する。主推定器はサーバーのMicro/Meso/Macro三階層LSTMを維持する。標準participantは `p001`。外部APIキーは不要。

## 追加した操作

- 「生活の気づき」タブから、晴れ・くもり・雨・雷を1タップで記録できる。任意日記は要求しない。疲労など5尺度は別の質問で回答し、各項目をスキップできる。
- 同じタブで自動質問・位置収集・質問通知・提案のON/OFF、質問上限・間隔を設定する。初期は位置・通知OFF。質問は4回/日、その内提案2回/日、間隔60分。
- 「今の質問に回答」はキーボードを開かずに回答する入口。通知をタップしても開ける。期限切れの質問は取得し直す。
- 「履歴・傾向・トポロジーを見る」はサーバーの `/research/p001/insights` を開く。従来の5尺度の履歴・訂正画面へも移動できる。
- キーボードも `currentState`, `weatherMood`, `typingReason`, `supportOutcome` に対応。設定済みサーバーが質問なし・通信失敗を返した場合、競合するローカル自動質問を出さない。URL未設定時だけ既存のローカル機能を利用する。

## 場所クラス

`LocationContextCollector` がCore Locationの訪問イベントを受け、端末内の `AutomaticPlaceMap` に匿名ノードを追加する。座標・距離で集約し、地点の名称入力は不要。100m以上を基本とし、測位誤差を加味して近いものを同一クラスにする。精度150m超は新しい場所と断定しない。

サーバーには `place_id / phase / accuracy_m / occurred_at` を送り、緯度経度を送らない。場所の中心座標はApp Groupの端末データに保持されるので、アプリデータを削除すると対応が失われ、新しい場所IDになる。再インストールをまたぐ同一性が必要なら端末バックアップを保持する。

1. タブで「場所の自動分類」をONにし、使用中の許可を選ぶ。
2. 背景でも訪問を受ける場合は「背景の位置検出を許可」から「常に」の許可を選ぶ。初回から必須にはしない。
3. キーボードを使わずに外出・滞在・帰宅する。CLVisitの通知は遅れることがあり、到着と出発がまとめて届く場合もある。
4. 通信が切れても単独イベントをoutboxに残し、次の同期で送る。通過しただけのGPS更新は滞在として記録しない。

期待：サーバーの場所マップに匿名クラスと移動辺が増え、曜日・時刻の履歴から行き先の候補が出る。命名・承認は要求されない。

意図しない状態：権限拒否・低精度・未配信なのに、本人の到着先や外出を確定表示すること。OSからイベントが来ない場合はデータ不足として扱う。ドア開閉だけで本人の外出を確定しない。

## 通知

`ResearchNotificationCoordinator` は前面時の60秒間隔、訪問/有意な位置変化のコールバック、BGAppRefreshの機会に質問を同期する。内容を表示するローカル通知は本人がONにした場合だけ。通知本文は詳細な気分・場所を含めない。

BGAppRefreshの「15分」は希望時刻であり保証ではない。強制終了・省電力・バックグラウンド更新OFF・通信不能時に、任意の時刻の通知を保証する仕組みではない。APNsや常時稼働サーバーからのpushサービスは追加していない。

同一質問IDを端末とサーバーで共有する。通知予約・表示・回答・後回しを区別し、通知予約も上限枠を確保する。提案を選択した後、実行したか、役立ったかを別に回答する。停止設定はWeb/親アプリ/キーボードに反映する。

## ビルド・テスト

既存のMozcビルド手順は変更しない。XcodeGenを利用し、iOS 15以降を対象とする。

```bash
./scripts/generate_xcode_project.sh
xcodebuild test -project MozcFlickKeyboard.xcodeproj -scheme MozcFlickKeyboard -destination 'platform=iOS Simulator,name=iPhone 16' CODE_SIGNING_ALLOWED=NO
```

期待：`** TEST SUCCEEDED **`。新規 `ResearchWorkflowTests` が、サーバー形式の質問デコード、天気と状態尺度の分離、匿名場所の成長・復元、座標を含まない送信形式を検証する。Simulator名はインストール済みの端末に合わせる。

意図しない出力：`** TEST FAILED **`、`No such module`、`Unable to find a destination`、署名のエラー。順にコード/ターゲット・プロジェクト生成・Simulator・Signing設定を確認する。iOS実機用MozcライブラリをSimulatorへリンクしない既存のSDK別設定を維持する。

実機ではプロジェクトを開き、本人のSigning Team・App Groupを既存手順で指定してインストールする。新しいInfo.plistには位置許可説明、background fetch/location、BGTask識別子が追加されている。PrivacyInfo.xcprivacyはホストアプリに同梱する。

### 実機で確認する順番

1. Backend URLをMacBookに向け、Tailscaleから `/health` に接続できることを確認する。
2. 雷を記録し、サーバーのweather履歴にangryが入り、疲労の正解が自動生成されないことを確認する。
3. 現在状態をキーボード/親アプリ双方から回答し、5尺度のJSONが学習ラベルになることを確認する。
4. 通信断で回答・訪問イベントを作り、アプリ終了後に再起動して再送されることを確認する。同じevent_idを重複集計しない。
5. 通知をONにし、アプリを背景へ。通知のタップで質問へ移動できること、停止で新規予約しないこと、同じIDをキーボードに重複表示しないことを確認する。
6. 入力の修正・未確定文字の削除を行い、通常入力と質問回答の操作が区別されることを確認する。
7. 外出・帰宅を数日繰り返し、場所クラスが再利用され、新しい滞在場所では自動で増えることを確認する。権限拒否・低精度・遅延配信時も確認する。

この実装環境ではSwift全ファイルの構文解析とサーバー/ブラウザの検証を行った。Xcode/iOS SDKがないため、XCTest・署名・実機の位置/通知の検証は未実施。PRにもこの範囲を明記する。

## 設計上の区別

気分の雷は怒り・いらだちであり、雨より強い疲労ではない。削除は誤入力だけでなく推敲・変換修正を含む。予測された行き先は観測された到着ではない。生活クラスは固定特徴の増殖型マップであり、LSTMの重み更新による表現の変化を新しい習慣と扱わない。
