# 三階層生活状態モデルとの接続

サーバー側の対応ブランチと一緒に使用する。既存の変換エンジンには変更しない。

- キーボードはサーバーの `currentState` を受け、現在の気分・疲労・ストレス・集中度・眠気を各1〜5で回答する。夜の `nightReflection` は「今日全体」として別に保存する。
- 回答は既存の永続送信キューを使用する。質問IDを端末に保存し、回答送信待ち中の再出題を防ぐ。「あとで」は30分後まで抑止する。
- 「くらしのログ」右上の「研究」で、同じ接続先の `/research/{participant}` を開く。状態、本人回答のグラフ、4種類の比較、活動・状態の訂正、PMTT、学習状況、全種類のエクスポート、提案停止・再開を操作できる。
- 回答データは `question.kind=currentState|nightReflection`、`answer.free_text` に5項目のJSONとして保存する。現在と1日全体は混在させない。
- 親アプリ/キーボードが動作した時に `/api/heartbeats` へ観測状態を送る。アプリが閉じた後の継続実行を保証するものではない。フルアクセスなしでは通信できず、サーバー側は観測不明として扱う。
- HealthKit・予定・電池は項目ごとの取得時刻を付ける。別の項目の更新によって古い値が新鮮に見えることを防ぐ。
- サーバーの休憩提案に回答すると、既存Narrative経路で `accepted / declined / deferred / stop` を記録する。停止は研究画面から再開できる。
- エクスポートには入力本文などが含まれる。共有先を選ぶ操作は本人が行う。外部AIへの送信は実装しない。

## 接続

iPhoneのBackend URLはMacのままでよい。Macサーバーの `research_upstream` をUbuntuへ設定し、UbuntuからMacの記録を差分取得する。詳細は `switch_bot_python/docs/research.md`。

## 検証状況と残る確認

この開発環境にはmacOS/Xcode/iOS SDKがない。iOSのコンパイル・XCTest・署名・実機操作・WKDownloadの共有画面は未検証。新しい `ResearchStateTests` を追加した。Macで次を実施する。

1. XcodeGenでプロジェクトを再生成し、Simulatorのビルドとテスト。
2. 実機で現在状態/夜の5項目、回答の再送、同一IDの再表示防止、あとで30分、質問OFFを確認。
3. Mac/Ubuntu接続断時の表示、研究画面、訂正、エクスポート共有、提案の停止/再開を確認。
4. HealthKit等の権限拒否時、フルアクセス無効時、端末ロック時の挙動を確認。

通知によるバックグラウンド出題は追加していない。キーボード表示時に質問を取得するため、使わない時間は欠測となる。
